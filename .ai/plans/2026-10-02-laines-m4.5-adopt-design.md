# L.AI.nes M4.5 — `adopt` and the shared `.ai/` round trip (design)

**Status:** approved in conversation 2026-10-02; written for review before the implementation plan.
**Builds on:** `2026-09-29-laines-spec.md` (v1 spec) and M1–M4 as built. Where this document and
the v1 spec differ, this document wins and the plan updates the spec.

## 1. Purpose

Two gaps surfaced on the first real use case (`~/work/myapp`, an existing project folder):

1. **Existing projects.** `init` only creates fresh containers. A user with an existing checkout
   wants that folder to *become* the container, its current contents becoming `lane_1`, with room
   for `lane_2`… beside it — without re-cloning, and without losing uncommitted work.
2. **Knowledge in PRs.** Lanes share the container's `.ai/` while they work (spec §7.2), but when
   the repository commits its own `.ai/`, knowledge written in the container never reaches the repo.
   It must be able to travel out in a PR, and knowledge merged upstream must come back in.

## 2. Decisions (user-approved)

| Topic | Decision |
|---|---|
| Non-git project | `adopt` requires a git repo with a reachable `origin`; otherwise exit 2 with the setup steps (`git init`, first commit, add remote, push). laines never creates repos or pushes. |
| The move | Two atomic renames; `lane_1` is the original directory, untouched. Always named `<lanePrefix>1` (default `lane_1`). No `--yes`; `--dry-run` is the preview. |
| Existing `.ai/` | The project's `.ai/` (tracked and untracked) seeds the container's shared `.ai/`; untracked files then leave `lane_1`; tracked ones stay (git owns them). |
| Live vs committed `.ai/` | The container's `.ai/` is the live knowledge base. A lane's committed `.ai/` is changed only by `laines ai sync`. |
| Round trip | `laines ai sync <lane>`: an explicit three-way sync (container ↔ lane, against a stored base) with conflict detection — not a one-way export, not continuous sync. |
| `init` | When the remote's default branch commits `.ai/`, the new container's `.ai/` is seeded from it instead of a blank layer. |
| Scope | M4.5 = `adopt` + `ai sync` (CLI and MCP) + `init` seeding + doctor checks + docs. |

## 3. `laines adopt <dir>`

```
laines adopt <dir> [--id <id>] [--agents claude,codex,gemini] [--dry-run] [--format json|table]
```

Human-only: CLI only (no MCP tool), Claude deny rules for `laines adopt` (and the `npx` forms), a
registry entry with `humanOnly: true`. No container exists before it runs, so capabilities and
`locked` do not apply.

### 3.1 Checks (exit 2, nothing touched, unless noted)

- `<dir>` exists and is a directory; resolved through `realpath`; not `/`, not the home directory.
- `<dir>/.git` is a **directory** (a worktree's or submodule's `.git` file is refused) and
  `git rev-parse --show-toplevel` equals `<dir>`.
- No ancestor of `<dir>` is a git repository or a L.AI.nes container; `<dir>` has no `.laines/`.
- `origin` exists and `git ls-remote --exit-code origin` succeeds (`GIT_TERMINAL_PROMPT=0`). On
  failure: the setup steps and the git error.
- No merge, rebase, cherry-pick or bisect in progress in `<dir>`.
- A leftover `.<name>.laines-adopt-*` sibling (an interrupted adopt) → exit 3 with the one `mv`
  that restores it.
- **Warnings, not refusals:** commits that exist on no remote (they stay in `lane_1`; `lane_2+`
  clones won't have them until pushed); Python virtualenvs found (directories containing
  `pyvenv.cfg`, depth ≤ 3, skipping `node_modules` and `.git`) — they hold absolute paths and must
  be recreated.

### 3.2 Flow

1. **Plan** (also the `--dry-run` result): container id and port block, lane name, the `.ai/`
   decision (§4.1), lane-local collisions (§3.3), warnings. Dry run stops here, exit 0, no writes.
2. **Claim** the container id and port block in the machine index (same as `init`).
3. **Move** — `rename(<dir>, <parent>/.<name>.laines-adopt-<timestamp>)`, `mkdir(<dir>)`,
   `rename(<tmp>, <dir>/<lane>)`. Each rename is atomic on one filesystem (the temp is a sibling, so
   the same filesystem). `lane_1` keeps everything: uncommitted changes, stashes, ignored files.
4. **`.ai/`** — §4.1.
5. **Container** — the same writes as `init` (dot-ai layer, `.laines/`, board, runbook, templates,
   agent blocks, deny rules, `.mcp.json`), reusing `init`'s code. When `.ai/` was seeded, dot-ai is
   brought up to date over the existing layer instead of initialised blank (the plan verifies which
   `dot-ai` command does this without overwriting content).
6. **Register the lane** — number 1, the lane's port range, `branch` = the current branch (or the
   default branch when HEAD is detached), `state: active`, `status: idle`; write lane files
   (`writeLaneFiles`, which also writes the exclude block and merges `.claude/settings.local.json`
   and `.mcp.json`); record the `ai sync` base (§4.3). Busy lane ports are a warning, not a refusal
   (nothing is started).
7. **Record** — board activity ("lane_1 adopted from the existing checkout"), audit `adopt`.
8. **Output** — paths, ports, warnings, next steps: recreate virtualenvs; stop old dev servers and
   reopen editors on `<dir>/lane_1`; Claude's saved project memory for `<dir>` now belongs to the
   container session; `laines create` for more lanes.

### 3.3 Lane-local collisions

Before lane files are written, any **untracked** `CLAUDE.local.md`, `AGENTS.md`, `GEMINI.md` or
`.laines.env` at the lane root is renamed to `<name>.pre-laines` (never overwritten) and reported.
`.claude/settings.local.json` and `.mcp.json` are merged as `writeLaneFiles` already does. Tracked
files are never touched (existing rule).

### 3.4 Rollback

- **Any failure before the lane is registered** (step 6 complete): undo in reverse — remove the
  container files written, restore `.ai/` changes, rename `<dir>/<lane>` back through the temp to
  `<dir>`, release the machine-index claim. The error names the failing step. The restore is
  verified (the original path exists with its `.git`).
- **After registration:** keep the container; the error names the fix (`laines doctor`,
  `laines refresh <lane>`).
- **A crash between renames** leaves the project in the hidden sibling; §3.1 detects it on the next
  `adopt`, and `doctor` run from the parent folder is not involved (no container exists).

## 4. The shared `.ai/`

### 4.1 Seeding

- **adopt, project has `.ai/`:** copy the whole `<lane>/.ai/` (tracked and untracked, no symlinks
  followed — symlinks are reported and skipped) to `<container>/.ai/`. Then delete the **untracked**
  entries under `<lane>/.ai/` (they now live in the container); tracked files stay. Lane-owned
  `context/` and `plans/` content that was untracked is copied to the container's `.ai/context/` and
  `.ai/plans/` respectively (it was the project's local working state, not a lane's).
- **adopt, no `.ai/`:** the container gets a fresh dot-ai layer, as `init` does.
- **init, remote commits `.ai/`:** after the remote is validated, read the default branch's `.ai/`
  tree (`git archive` / a shallow fetch into a temporary directory under the machine config dir,
  removed afterwards) and seed `<container>/.ai/` from it before the dot-ai update. If the remote
  cannot be read, fall back to a fresh layer with a warning.

### 4.2 The rule for agents

The container's `.ai/` is the live knowledge base: agents in every lane read and write there. A
lane's committed `.ai/` files are output — agents do not edit them by hand; `laines ai sync <lane>`
does. The lanes block, the lane-local instructions and the lane `.ai/README.md` say so, plus "run
`laines ai sync <lane>` before opening a PR".

### 4.3 `laines ai sync <lane>`

```
laines ai sync [lane] [--dry-run] [--format json|table]       MCP: laines_ai_sync { lane?, dry_run? }
```

Applies only when the lane's repository commits `.ai/` (any tracked file under `.ai/`). Otherwise
exit 0 with "this repository does not commit .ai/: knowledge stays in the container".

**Synced set:** every regular file under `.ai/` except `context/**`, `plans/**`, any path segment
starting with `_`, `.ai/README.md`, `.ai/.lane.json`. Paths are compared relative to `.ai/`.

**Base:** `.laines/ai-sync.json` = `{ "version": 1, "base": { "<rel>": "sha256:<hex>" } }` — the
content of the synced set at the last successful sync (per container, not per lane: the base is
"what the repo and the container last agreed on"). Written atomically, only after both sides are
written. adopt and seeding `init` write the initial base.

**Per file** (`c` = container, `l` = lane working tree, `b` = base; absent = deleted):

| Condition | Action |
|---|---|
| `c == l` | none (base := c) |
| `l == b`, `c != b` | container changed → write `c` to the lane (or delete) |
| `c == b`, `l != b` | lane changed (e.g. pulled main) → write `l` to the container (or delete) |
| `c != b`, `l != b`, `c != l` | **conflict** → neither side touched; listed |

Any conflict → exit 3 after applying all non-conflicting files, listing each conflict with the
two paths to compare and how to resolve (edit the container copy to the wanted content, make the
lane copy equal to it, re-run). Base entries for conflicting files are not updated.

**Safety:** containment checks on both roots (lane: `assertLaneDir`); never follows symlinks (a
symlink on either side is a conflict-like refusal for that file); refuses a lane with a merge or
rebase in progress (exit 3); writes files atomically; never touches anything outside the two
`.ai/` trees.

**Result:** `{ lane, applies, toLane: [rel], toContainer: [rel], deleted: { lane: [], container: [] }, conflicts: [{ path, container, lane }], dryRun }`. Board activity line when anything moved; audit `ai-sync`.

**Gates:** new capability `aiSync` (default `true`) in `config.capabilities`, checked by the
registry for CLI and MCP; not `humanOnly`; not refused by `locked`. Over MCP, only lanes of the
bound container.

## 5. Doctor

- **Lane check:** for a repository that commits `.ai/`, the number of synced-set files where
  container and lane differ → informational detail "`.ai/` differs in N file(s): run `laines ai
  sync <lane>`" (does not fail the check).
- **Container check:** a malformed `.laines/ai-sync.json` fails a new `ai-sync` check.

## 7. Testing

All against real git repositories and real directories (temporary roots):

- **adopt refusals:** not a repo; `.git` is a file (worktree); nested in a repo; already a
  container; no `origin`; unreachable `origin`; operation in progress; leftover temp sibling (exit 3).
- **adopt results:** uncommitted changes, stashes and ignored files survive in `lane_1`;
  `.pre-laines` backups for untracked collisions; tracked/untracked/none `.ai/` cases land per §4.1;
  virtualenv warning; unpushed-commit warning; the container passes `laines doctor`; `laines create`
  then gives `lane_2` a normal clone; dry run is a no-op (directory listing and git status
  byte-identical).
- **adopt rollback:** a failure injected after each step restores the original directory exactly
  (file listing and `git status` identical) and releases the machine-index claim.
- **init seeding:** a remote that commits `.ai/` seeds the container; an unreadable remote falls back
  with a warning.
- **ai sync:** every row of §4.3's table including deletions; conflicts leave both sides untouched
  and exit 3; excluded paths never move; symlinks refused; repository without `.ai/` → no-op; base
  updated only on success; MCP tool and `aiSync` capability gate; dry run is a no-op.
- **End to end:** adopt → `lane_2` → knowledge added in the container → `ai sync lane_2` shows in
  `lane_2`'s `git diff` → commit, push, pull into `lane_1` → `ai sync lane_1` agrees with no conflict.
- **Coverage guards:** registry/CLI leaf coverage, deny rules for `adopt`, MCP tool list (+1 tool).
