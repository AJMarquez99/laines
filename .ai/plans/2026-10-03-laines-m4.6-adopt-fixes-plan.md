# L.AI.nes M4.6 — fixes from the myapp adoption (implementation plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Make an adopted container safe for lane agents: `lane_1` keeps the project's Docker Compose
identity, `ai sync` never commits index rows for files the repository lacks, and the smaller
issues from the first real adoption are fixed.

**Source:** `.ai/audits/2026-10-03_myapp-adoption.md` (issues 1–5). User approved fixing 1, 2, 3
and 5 on 2026-10-03 ("Go ahead").

**Architecture:** Three tasks on the existing code: lane state gains an optional Compose project
name set by `adopt`; laines' own container files move to `_`-prefixed names (the dot-ai convention's
private files, indexed in a gitignored `_README.md` and already outside the `ai sync` set), with a
migration in `refresh`; the git exclude block lists only files the repository does not track;
doctor notes and `ai sync` entries get explicit labels.

**Tech stack:** Node ≥20 ESM, vitest, real git in tests (existing helpers in `test/helpers.js`).

**Spec:** `.ai/plans/2026-09-29-laines-spec.md` + `.ai/plans/2026-10-02-laines-m4.5-adopt-design.md`.

## Global Constraints

- Everything in the M1–M4.5 Global Constraints still applies: exit codes `0/1/2/3/4`, JSON by
  default with `--format table`, `--dry-run` a true no-op, commands return data and never print,
  `readJson`/`writeJson`/`writeFileAtomic` for files, every `lanes.json` change through
  `updateLanes`, git only through `deps.git`/`deps.gitAsync`, every command through the registry's
  `invoke`, conventional commits staged by explicit path.
- Never overwrite or delete a user's file: migrations rename (never overwrite an existing target) and
  report what they could not do.
- Commit trailer, exactly: `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
- The user's shell aliases `rm`/`cp` to interactive prompts: `command rm -f` / `command cp` in Bash,
  Node `fs` in tests.

## Decisions (controller rulings, 2026-10-03)

- **Issue 2 fix = `_`-prefixed laines files, not a `_README.md` index of the old names.** Listing the
  old names only in `_README.md` fights dot-ai: `dot-ai index` re-adds `TODO: describe` rows for any
  non-`_` file to `README.md`, and `dot-ai doctor` warns "unlisted in index". `_` files are
  dot-ai's private class: never in `README.md`, indexed in `_README.md`, excluded from `ai sync` by
  the existing `_`-segment rule. Cost if wrong: a rename migration for existing containers.
- **Issue 1 fix = a per-lane Compose project override recorded by `adopt`.** Existing adopted
  containers (only myapp exists) are migrated by hand once after merge; no permanent CLI flag.

## Review Focus

1. A container made before M4.6 (old file names, rows in `README.md`): `refresh` migrates it, and a
   user who customised `templates/lane-*.md` keeps the customisation.
2. A container where a `_lane-management.md` already exists next to the old name: nothing is
   overwritten; doctor/refresh report it.
3. A project whose `.env` or compose file already names the Compose project: adopt records that name,
   not the folder's basename.
4. A repository that tracks `AGENTS.md`/`GEMINI.md`/`.ai/README.md`: the exclude block omits them,
   doctor does not call the block outdated.
5. Sourcing `.laines.env` in an adopted `lane_1` keeps the original Compose project.

### Task 1: adopted `lane_1` keeps the project's Compose identity (audit issue 1)

**Files:** `src/commands/adopt.js`, `src/lib/lane-files.js` (`laneVars`), lane-state schema
(`src/lib/lanes-state.js` and/or `src/lib/schema.js`), every caller of `laneVars`/`laneEnv`/
`writeLaneFiles` that builds the lane argument (create, refresh, adopt, hook environment), README +
spec (§8.3 variables, §10.4 adopt), `templates/lane-management.md` (adopt section). Tests:
`test/adopt.test.js`, `test/lane-files.test.js` (or wherever `laneVars` is tested), refresh test.

- Lane state gains optional `compose: string` (absent for laines-created lanes; schema must accept
  old files without it).
- `laneVars` uses `COMPOSE_PROJECT_NAME = lane.compose ?? composeProject(containerId, number)`. Make
  sure every path that renders `.laines.env` or the hook environment passes the lane's `compose`
  through (create, refresh, adopt, hooks).
- `adopt` computes the project's current effective Compose project name, in this order:
  1. `COMPOSE_PROJECT_NAME=` in the project's `.env` (first matching line; strip optional quotes);
  2. a top-level `name:` in the first existing of `compose.yaml`, `compose.yml`,
     `docker-compose.yaml`, `docker-compose.yml` (regex on a line starting `name:` at column 0;
     strip quotes);
  3. Docker Compose's default: the original folder's basename lowercased with every character
     outside `[a-z0-9_-]` removed (if empty, skip — leave `compose` unset).
  It records it as `lane_1`'s `compose` before `writeLaneFiles`, shows it in the plan/dry-run
  result (`compose` field) and table output ("compose: myapp (kept from the original checkout)").
- `refresh` preserves `compose` (it reads lane state; no change needed beyond passing it through —
  verify with a test).
- Tests: adopt from a folder named `My App` with no `.env`/name → `compose: "myapp"` and
  `.laines.env` has `COMPOSE_PROJECT_NAME="myapp"`; `.env` with `COMPOSE_PROJECT_NAME=custom` →
  `custom`; compose file `name: "fromfile"` → `fromfile`; a laines-created lane still gets
  `<id>-l<n>`; `refresh lane_1` keeps the adopted name in `.laines.env`; dry run shows it.
- Docs: README adopt row/quick start and lane-management's adopt paragraph: "lane_1 keeps the
  project's Docker Compose project name, so existing volumes and containers stay attached; other
  lanes get their own (`<id>-l<n>`)."

### Task 2: laines' container files become `_`-prefixed (audit issue 2)

**Files:** `src/commands/init.js` (`LANE_TEMPLATES`, `CONTAINER_FILES`, `writeContainer`'s
`addIndexRow` calls), `src/lib/lane-files.js` (`writeLaneFiles` template lookup), `src/lib/ai-tree.js`
(`LAINES_OWNED`), `src/lib/paths.js` (if it names the runbook), `src/commands/refresh.js` (migration),
`src/commands/doctor.js` (flag unmigrated containers), `src/lib/agent-files.js` (index helpers),
`templates/lanes-block.md`, `templates/lane-local-instructions.md`, `templates/lane-ai-readme.md`,
`templates/lane-management.md`, README, spec. Tests: init, adopt, refresh, doctor, ai-tree,
agent-files, create, e2e.

- Container file names: `.ai/runbooks/_lane-management.md`, `.ai/templates/_lane-ai-readme.md`,
  `_lane-context-readme.md`, `_lane-plans-readme.md`, `_lane-local-instructions.md`. Package
  template sources under `templates/` keep their current names.
- Their rows go in the folder's `_README.md` (create it if absent with dot-ai's private seed, exactly:
  `# Private index\n\nLocal-only — gitignored by the \`_*\` rule. Indexes this folder's \`_\` files so they\nnever appear in the committed \`README.md\`.\n\n## Index\n\n| File | Answers |\n|---|---|\n`),
  never in `README.md`.
- `writeLaneFiles`: the container's customised copy is looked up as `_<name>` first, then the old
  `<name>` (unmigrated container), then the package template.
- `LAINES_OWNED` in `ai-tree.js`: keep the old names (unmigrated containers must still not sync them);
  the new names are excluded by the existing `_` rule — add a test asserting both.
- **Migration** (a function in a lib module, called by `refresh` for the container before its lane
  work, and safe to run repeatedly): for each old-name file present in the container's `.ai/`:
  if the `_` name does not exist, rename old → new; if both exist, leave both and add a warning
  ("both X and _X exist: keep one by hand"). Remove laines' row for that file from the folder's
  `README.md` (only a row whose link target is exactly the old file name) and add the `_` row to
  `_README.md` (no duplicate). Result lists what was migrated; refresh includes it in its output.
  `adopt` and `init` write the new layout directly.
- `doctor`: a container that still has an old-name file (or a laines row in `README.md`) gets a
  failing-or-warning detail on the existing `dot-ai`/agent-files check (choose the check that
  already covers container files) saying "run `laines refresh <lane>` to move laines' files to
  `_` names". Fresh containers pass.
- Update every reference to the runbook/template paths in templates, brief, README, spec.
- **Regression test (from the audit):** adopt a repo that commits `.ai/` (with `runbooks/` and
  `templates/` READMEs), run `ai sync lane_1`, and assert every index row in every
  `<lane>/.ai/*/README.md` links to a file that exists in the lane; and that `_README.md` files are
  not synced to the lane.
- Migration test: a container laid out the old way (write the old names + README rows by hand, or
  build with the old code path simulated) → `refresh` → new names, rows moved, a customised template's
  content preserved, second refresh is a no-op.

### Task 3: exclude block, doctor notes, sync reasons, docs (audit issues 3 and 5)

**Files:** `src/lib/lane-files.js` (`upsertExclude`), `src/commands/doctor.js`, `src/lib/format.js`,
`src/lib/ai-tree.js` (`planSync`) / `src/commands/ai-sync.js`, README, roadmap
(`.ai/plans/2026-09-29-laines-roadmap.md`), `.ai/plans/README.md`, `.ai/audits/`. Tests: lane-files,
doctor, ai-sync, format tests where they exist.

- **Exclude block:** a function `laneExcludes(deps, laneDir)` returns `LANE_EXCLUDES` minus exact-file
  entries (no trailing `/`, no `*`) that the repository tracks (`isTracked`). `upsertExclude` writes
  that list; doctor's "exclude block outdated" check compares against the same function. Test: a repo
  tracking `AGENTS.md` and `.ai/README.md` → block omits `/AGENTS.md` and `/.ai/README.md`, keeps
  `/.ai/context/`, `/*.pre-laines*`; doctor ok.
- **Doctor notes:** a check may carry an informational note distinct from pass/fail. The lane
  drift detail (`.ai/ differs in N file(s): …`) is a note: JSON gains `note: "<text>"` on the check
  (keep `detail` backward compatible as today), and the table formatter renders notes with `•`
  (e.g. `✓ lane:lane_1  ok` then `  • .ai/ differs in 2 file(s): run …`). Test the formatter.
- **Sync reasons:** the `ai sync` result gains `why: { "<rel>": "added" | "changed" | "deleted" }`
  for every path in `toLane`, `toContainer` and the deletions, computed from the side being copied
  (added = absent on the receiving side, deleted = absent on the sending side). Table output shows
  the word after each path. Test.
- **Docs:** README/spec mention the per-check note and `why`; roadmap gets an M4.6 row ("Fixes from
  the first real adoption: Compose identity for adopted lane_1, `_` laines files, exclude block,
  doctor notes, sync reasons" — Done); `.ai/plans/README.md` index row for this plan.
